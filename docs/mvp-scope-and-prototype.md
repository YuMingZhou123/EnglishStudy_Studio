# MVP 范围确认与页面原型清单

版本：v0.1  
日期：2026-05-27  
状态：初稿，待确认

## 1. 文档目标

本文档用于在正式开发前锁定第一版 MVP 的产品范围、目标用户、核心链路、页面原型和验收标准，避免第一阶段功能过多导致开发发散。

## 2. MVP 核心判断

第一版 MVP 只验证一个核心问题：

> 用户是否愿意通过“听一句英语音频，在真实语境中填空或听写”的方式持续学习单词和提升听力。

因此第一版的主功能是“语境听写”，其他功能都围绕它服务。

## 3. 目标用户

### 3.1 第一版建议目标用户

第一版建议优先面向：

- 大学生
- 职场新人
- 通用初中级英语学习者

其中产品表达先偏通用初中级用户，不在第一版强绑定某个考试。

### 3.2 用户特征

- 有背单词需求，但觉得传统背词枯燥。
- 听力基础较弱，听到句子后抓不住关键词。
- 希望用碎片时间练习英语。
- 对 AI 学习工具接受度较高。

### 3.3 第一版暂不重点服务

- K12 低龄学生。
- 高阶雅思托福用户。
- 专业翻译学习者。
- 学校、机构、企业管理员。

## 4. 第一批内容方向

### 4.1 推荐内容

第一批内容建议选择“日常 + 校园 + 职场基础”混合场景。

原因：

- 覆盖面广。
- 不依赖复杂考试体系。
- 便于快速制作 100 到 300 条高质量句子。
- 适合初级、中级、高级三种听写难度复用。

### 4.2 内容分类

第一批建议包含：

- 日常交流
- 校园学习
- 职场沟通
- 面试基础
- 旅行生活

### 4.3 内容规模

MVP 内容量建议：

- 句子：100 到 300 条。
- 核心词：300 到 800 个。
- 场景：5 到 8 个。
- 每条句子至少配置 1 个目标词。

## 5. MVP 必做功能

### 5.1 用户端

- 用户注册 / 登录。
- 学习目标选择。
- 当前水平选择：初级 / 中级 / 高级。
- 学习首页简版。
- 语境听写入口。
- 初级：核心关键词填空。
- 中级：多个关键词填空。
- 高级：整句听写。
- 音频播放。
- 慢速播放。
- 首字母提示。
- 中文提示。
- 答案提交。
- 答题反馈。
- 完整句子展示。
- 中文翻译展示。
- 目标词释义展示。
- 错词自动入库。
- 错词本。
- 基础学习记录。

### 5.2 管理端

- 管理员登录。
- 句子列表。
- 新增句子。
- 编辑句子。
- 发布 / 下架句子。
- 单词列表。
- 新增 / 编辑单词。
- 场景分类管理。
- 音频上传到 MinIO。
- 句子绑定音频。

### 5.3 后端能力

- ASP.NET Core Web API。
- Swagger / OpenAPI。
- PostgreSQL 数据库。
- EF Core 迁移。
- MinIO 文件存储。
- 用户认证。
- 题目生成。
- 答案判定。
- 答题记录。
- 错词入库。

## 6. MVP 暂不开发功能

第一版明确不做：

- 微信小程序。
- 原生 App。
- 会员支付。
- AI 口语陪练完整版本。
- 发音评测。
- 教师端。
- 班级系统。
- 机构后台。
- 排行榜。
- 成就系统。
- 复杂学习报告。
- AI 自动生成全部内容。
- 多人实时语音。
- 离线学习。

说明：AI 口语可以保留为后续 P3 阶段，不进入第一版核心 MVP。

## 7. 核心用户链路

### 7.1 新用户链路

1. 用户进入网站。
2. 注册 / 登录。
3. 选择学习目标。
4. 选择当前水平。
5. 进入学习首页。
6. 点击今日语境听写。
7. 完成 5 到 10 道题。
8. 查看答题反馈。
9. 错词进入错词本。

### 7.2 语境听写链路

1. 系统获取下一题。
2. 页面播放音频。
3. 用户根据难度输入答案。
4. 用户提交。
5. 后端判题。
6. 页面展示结果。
7. 答错词进入错词本。
8. 用户进入下一题。

### 7.3 后台内容链路

1. 管理员登录后台。
2. 新增句子。
3. 上传或配置音频。
4. 配置目标词和难度。
5. 发布句子。
6. 用户端可以获取该题。

## 8. 页面原型清单

### 8.1 用户端页面

#### 8.1.1 登录页

目标：

- 让用户完成登录或注册。

页面元素：

- Logo / 产品名。
- 手机号或邮箱输入。
- 验证码或密码输入。
- 登录按钮。
- 注册入口。

#### 8.1.2 引导页

目标：

- 收集用户学习目标和当前水平。

页面元素：

- 学习目标选择。
- 当前水平选择。
- 开始学习按钮。

#### 8.1.3 学习首页

目标：

- 告诉用户今天应该做什么。

页面元素：

- 今日任务。
- 连续学习天数。
- 今日完成进度。
- 语境听写入口。
- 错词复习入口。
- 当前等级。

#### 8.1.4 语境听写页

目标：

- 完成听音频、填空、提交和反馈。

页面元素：

- 难度标识。
- 场景标签。
- 音频播放按钮。
- 慢速播放按钮。
- 题目句子或整句输入框。
- 首字母提示按钮。
- 中文提示按钮。
- 提交按钮。
- 下一题按钮。
- 答题反馈区。

#### 8.1.5 答题结果区

目标：

- 让用户知道答案、含义和错误原因。

页面元素：

- 正确 / 错误状态。
- 正确答案。
- 完整英文句子。
- 中文翻译。
- 目标词释义。
- 常见搭配。
- 加入生词本按钮。

#### 8.1.6 错词本页

目标：

- 让用户查看和复习错词。

页面元素：

- 错词列表。
- 掌握状态。
- 来源句子。
- 最近错误时间。
- 复习按钮。

#### 8.1.7 个人中心页

目标：

- 展示用户基础资料和学习设置。

页面元素：

- 昵称。
- 当前学习目标。
- 当前水平。
- 学习统计摘要。
- 退出登录。

### 8.2 管理端页面

#### 8.2.1 管理员登录页

页面元素：

- 账号输入。
- 密码输入。
- 登录按钮。

#### 8.2.2 管理后台首页

页面元素：

- 句子数量。
- 单词数量。
- 今日练习次数。
- 最近发布内容。

#### 8.2.3 句子管理页

页面元素：

- 句子列表。
- 搜索。
- 场景筛选。
- 难度筛选。
- 发布状态筛选。
- 新增句子按钮。
- 编辑按钮。
- 发布 / 下架按钮。

#### 8.2.4 句子编辑页

页面元素：

- 英文句子输入。
- 中文翻译输入。
- 场景选择。
- 难度选择。
- 目标词配置。
- 音频上传。
- 发布状态。
- 保存按钮。

#### 8.2.5 单词管理页

页面元素：

- 单词列表。
- 搜索。
- 新增单词。
- 编辑单词。
- 词性。
- 中文释义。
- 难度。

#### 8.2.6 场景分类页

页面元素：

- 场景列表。
- 新增场景。
- 编辑场景。
- 启用 / 停用。

## 9. 第一版数据模型范围

第一版只需要以下核心数据：

- 用户。
- 管理员。
- 场景。
- 单词。
- 句子。
- 句子目标词。
- 媒体资源。
- 听写记录。
- 用户词汇状态。

不需要第一版设计：

- 订单。
- 会员权益。
- 班级。
- 教师。
- 机构。
- 优惠券。
- 训练营。

## 10. MVP 验收标准

### 10.1 产品验收

- 用户可以注册登录。
- 用户可以完成初级、中级、高级语境听写。
- 用户可以播放音频。
- 用户提交答案后可以看到反馈。
- 答错词可以进入错词本。
- 用户可以查看基础学习记录。
- 管理员可以录入并发布句子。

### 10.2 技术验收

- 前端项目可以本地启动。
- 后端项目可以本地启动。
- Swagger 可以访问。
- PostgreSQL 可以连接。
- MinIO 可以访问。
- 音频可以上传到 MinIO。
- 前端可以播放 MinIO 中的音频。
- 答题记录可以保存到 PostgreSQL。

### 10.3 内测验收

找 5 到 10 名用户试用，观察：

- 是否能独立完成第一轮练习。
- 是否理解三种难度。
- 是否愿意继续做下一题。
- 是否认为这种方式有助于记单词。
- 哪些页面或按钮让用户困惑。

## 11. 开发前确认项

正式开发前建议确认：

- 第一批目标用户是否锁定为通用初中级用户。
- 第一批内容是否采用日常 + 校园 + 职场基础。
- 第一版是否不做 AI 口语。
- 第一版是否不做小程序。
- 第一版是否不做支付。
- 是否先用邮箱 + 密码登录，手机号登录后置。
- 第一批句子是否先人工整理。

## 12. 下一步

完成本文档确认后，进入工程搭建阶段：

1. 创建 `apps/web` Next.js 项目。
2. 创建 `apps/api` ASP.NET Core Web API 项目。
3. 创建 Docker Compose，启动 PostgreSQL 和 MinIO。
4. 创建数据库基础模型。
5. 跑通健康检查、Swagger、数据库连接和 MinIO 连接。

# 第一版内测执行手册

版本：v0.1
日期：2026-05-28
状态：第一版内测准备稿

## 1. 目标

本手册用于组织 5 到 10 名真实用户完成第一版内测，验证以下问题：

- 用户能否独立完成注册、登录、学习设置和第一轮听写。
- 用户是否理解初级、中级、高级三种难度。
- 用户是否能通过听一句英语、填关键词或整句听写完成练习。
- 用户是否觉得这种方式有助于在语境中记单词。
- 哪些页面、按钮、提示、音频体验会让用户困惑。

## 2. 内测前置条件

开始内测前，先在本地或测试环境完成以下检查：

```powershell
docker compose -f infra/docker-compose.yml up -d
dotnet run --project apps/api --launch-profile http
cd apps/web
npm run dev
```

另开终端执行：

```powershell
.\scripts\validate-mvp-content.ps1
.\scripts\import-mvp-content.ps1
.\scripts\generate-missing-audio.ps1
.\scripts\smoke-test.ps1 -IncludeTts
node .\scripts\ui-smoke-test.mjs
```

通过后再发给用户试用。

导出内测反馈表：

```powershell
.\scripts\export-beta-feedback-template.ps1
```

默认输出：

```text
feedback/internal-beta-feedback.csv
```

## 3. 参与用户

建议第一轮找 5 到 10 人：

- 2 到 3 名大学生。
- 2 到 3 名职场新人。
- 1 到 2 名通用初中级英语学习者。
- 尽量包含英语基础不同的人，避免只找英语很好的用户。

不建议第一轮找：

- 专业英语教师。
- 高阶考试用户。
- 只关心机构管理功能的人。

## 4. 测试账号安排

优先让用户自己注册账号，这样可以验证新用户链路。

如果只是快速演示，可以使用：

```text
learner@example.com / Pass123$
```

管理员演示账号：

```text
admin@example.com / Admin123$
```

不要把管理员账号发给普通内测用户。

## 5. 用户测试任务

每个用户按以下任务执行，建议总时长 15 到 25 分钟：

1. 打开 Web 首页。
2. 注册新账号，或使用演示账号登录。
3. 设置当前水平和学习目标。
4. 进入学习首页，确认是否知道下一步该做什么。
5. 完成初级听写 2 题。
6. 完成中级听写 2 题。
7. 完成高级听写 1 题。
8. 点击原速朗读和慢速朗读，确认音频体验。
9. 使用一次首字母提示。
10. 使用一次中文提示。
11. 故意答错 1 题，确认反馈是否看得懂。
12. 打开词汇本，确认错词是否进入。
13. 从词汇本进入复习，完成 1 题。
14. 打开学习记录，确认是否能看懂练习明细。
15. 说出最困惑的 1 到 3 个地方。

## 6. 观察重点

观察时不要只看用户说什么，也要记录用户卡在哪里：

- 是否知道点击哪个入口开始练习。
- 是否理解空格要填什么。
- 是否知道高级模式要输入整句。
- 是否能发现原速、慢速、首字母、中文提示。
- 提交后是否能理解分数、正确答案、翻译、目标词。
- 错词本和复习入口是否自然。
- 音频是否太快、太慢、太机械、太小声。
- 移动端页面是否有文字挤压、按钮难点、输入框难输入。

## 7. 反馈记录模板

每位用户记录一行：

| 字段 | 填写说明 |
| --- | --- |
| 用户编号 | U01、U02 等 |
| 用户类型 | 大学生 / 职场新人 / 通用学习者 |
| 英语水平 | 初级 / 中级 / 高级 / 不确定 |
| 是否独立完成 | 是 / 否 |
| 卡住步骤 | 写具体步骤编号 |
| 是否理解三种难度 | 是 / 部分 / 否 |
| 是否愿意继续做下一题 | 是 / 一般 / 否 |
| 觉得有用吗 | 有用 / 一般 / 没用 |
| 音频问题 | 无 / 太快 / 太机械 / 声音小 / 播放失败 |
| 页面问题 | 具体描述 |
| 内容问题 | 具体句子或单词 |
| 优先级 | P0 / P1 / P2 |
| 备注 | 用户原话或观察记录 |

## 8. 通过标准

第一轮内测可以认为通过的最低标准：

- 至少 5 名用户完成测试。
- 至少 4 名用户能独立完成第一轮听写。
- 至少 4 名用户能理解三种难度差异。
- 至少 3 名用户表示愿意继续做下一题。
- 没有 P0 阻断问题。
- P1 问题有明确修复计划。

## 9. 问题分级

P0：

- 用户无法登录。
- 无法进入听写。
- 无法播放或 fallback 音频完全不可用。
- 提交答案失败。
- 错词、记录等核心链路完全不可用。

P1：

- 用户明显理解错核心流程。
- 音频体验严重影响做题。
- 移动端主要页面难以使用。
- 内容错误影响答案判断。

P2：

- 文案不够清楚。
- 某些按钮位置不够顺手。
- 局部样式或反馈可以更好。
- 个别句子或翻译可以优化。

## 10. 内测后决策

完成第一轮内测后，只做三类决策：

- 必修：阻断用户完成主链路的问题。
- 优化：能明显提高继续练习意愿的问题。
- 后置：不影响第一版验证的扩展功能。

不要在第一轮内测后立刻扩展支付、小程序、机构端、复杂报告。先把语境听写闭环打磨顺。

汇总内测结果：

```powershell
.\scripts\summarize-beta-feedback.ps1
```

`passesMinimumGate` 为 `true` 时，说明内测结果达到本文档的最低通过标准。
